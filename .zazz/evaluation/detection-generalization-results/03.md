## First failing stage

Question framing. The shared request instruction for every `resolve_*` question says "answer each from the
supplied source alone". This question asks for a package's documented behavior, which the source does not
hold. The two contradict each other and the model followed the shared one. The offline tests used stubbed
answers and could not see it. Whether the model knows these packages is **not** answered by this run: the
run does not show that the idea fails, and it does not show that it works.

The answers also left `injection_protection` unknown when the call was resolved (2 records), so a correct call
answer alone did not give a finding.

## Next, for the owner

Contract §5 allows one redesign, with a new specification and **unused** held-out applications; these 25
fixtures are spent as evidence. It needs: an instruction selected per record that permits package knowledge
for this question only, a check that the family answer follows the call answer, and a small paid probe of
the framing before any other code. The candidate rule (`ed257a7`) passed every offline gate and can be
restored with the redesign. The evidence is in `_test-findings/detection-generalization-03/`.
